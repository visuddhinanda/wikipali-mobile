# 法音 · Chat 栏目设计文档（App / Web 一致）

> 版本：v1.0（2026-08-24）
> 范围：从 `README.md` §1.3「AI Chat」独立提取并细化。App 与 Web 共用同一套信息架构、视觉与文案。
> 前置文档：`README.md`（§4 响应式总览＝断点唯一真源、§6 技术栈、§7 接口映射）；`STATUS.md`（P0 现状）。

---

## 1. 定位与总体架构

Chat 栏目是「巴利经文 AI 问答」的核心入口，分为**引流层 + 对话层**两层，职责分离：

| 层 | 页面 | 职责 | 实现 |
|---|---|---|---|
| 引流层 | **首页**（问答广场） | 头部提示 + 输入框 + 社区问答列表，引导用户进入对话 | 独立列表组件，非 CopilotChat 职责 |
| 对话层 | **问答页** | 我的历史问题 + 问答区（流式对话 + 引用卡片） | 复用/定制 CopilotKit 对话层 |

**App 与 Web 保持一致**：同一套设计 tokens（`src/theme`）、同一套文案、同一信息架构；差异仅在「导航容器与响应式断点」——通过响应式分支一次实现，App（React Native）与 Web（`expo start --web` / react-native-web，或独立 Web 前端按本 spec 复刻）共用同一套组件树。

### 1.1 Chat 的四个入口（统一收口）

| 入口 | 落地页 |
|---|---|
| 底部 Tab「AI Chat」（凸起按钮） | 首页（问答广场） |
| 阅读器「就此段落提问」 | 问答页·新对话（携带段落 `passage id` 上下文） |
| 首页 / 问答页「我的提问历史」 | 问答页（历史列表选中态） |
| 社区问答列表卡片点击 | 问答页（该问题只读详情 + 底部「继续追问」） |

## 2. 页面一：首页（问答广场）

自上而下三个区域：**头部提示栏目 → 输入框 → 社区问答列表**。

```
┌─────────────────────────────────────────────┐
│  ① 头部提示栏目（Hero / 提示条）              │
│     标题 · 副标题 · 免责提示 · 示例问题 chips   │
├─────────────────────────────────────────────┤
│  ② 输入框（提出新问题）                       │
├─────────────────────────────────────────────┤
│  ③ 社区问答列表（问答广场 feed）              │
│     ┌───────────────────────────────┐      │
│     │ 问题摘要   [中文] [引用经文·2]  │      │
│     ├───────────────────────────────┤      │
│     │ 问题摘要   [Pali]            │      │
│     └───────────────────────────────┘      │
└─────────────────────────────────────────────┘
```

### 2.1 头部提示栏目内容

定位：一句话说明助手能做什么 + 引导提问 + 免责声明。具体文案（App / Web 完全一致）：

- **标题**：`法音 · 巴利经文问答`
- **副标题**：`基于三藏原文的 AI 问答，回答附经文出处，点击引用可跳转原文。`
- **免责提示条**（细线框 + 提示图标）：`回答由 AI 生成，仅供参考，请以原典为准。`
- **示例问题 chips**（可点击，点击即进入问答页并发送该问题）：
  1. `什么是四圣谛？`
  2. `缘起与十二因缘的关系？`
  3. `什么是无我（anattā）？`
  4. `慈经（Karaṇīyametta Sutta）讲了什么？`
- **（可选）能力标签**：`经文检索` · `术语释义` · `多语言（中/英/巴利）`

样式沿用主题：Hero 使用 `paperRaised` 卡片 + 朱砂色标题；chips 用 `paperSunken` 底 + `radius.pill`。

### 2.2 输入框

- **占位文案**：`提出一个新问题…`
- **组成**：多行输入框（自动增高，上限 5 行）+ 圆形发送按钮（朱砂色 `#8c3b2e`，向上箭头）。
- **交互**：
  - 点击 / 聚焦（未输入）→ 进入**问答页·新对话**；
  - 输入后回车 / 点发送 → 进入问答页并**立即发送**该问题。
- **语言标签（可选）**：发送前在输入框右侧显示识别到的提问语言（Pali / 中文 / English…），来自后端 `lang` 字段。

### 2.3 社区问答列表（问答广场 feed）

- **数据**：公开问题（`Chat` 表中 `is_public=1` 且已有回答）。
- **排序（顶部切换，可选）**：`最新` ｜ `最热`。
- **卡片字段**：
  - 问题摘要（1–2 行截断，`numberOfLines`）
  - 提问语言标签（pill）
  - 引用经文标识：有 citations → 显示 `📖 引用经文 · N`（赭石色）
  - 回答数 / 最后活跃时间（相对时间，可选）
- **交互**：点击 → 问答页·该问题只读详情（先展示已有回答，底部「继续追问」）。
- **加载**：下拉刷新 + 上拉无限滚动（分页）。
- **三态**：
  - 加载中：骨架屏（卡片占位）；
  - 空态：`暂无公开问题，来提第一个问题吧`（+ 引导按钮）；
  - 错误态：`加载失败` + 重试按钮。

## 3. 页面二：问答页

两个区域：**我的历史问题（侧栏/抽屉）+ 问答区（主对话区）**。

```
┌───────────────┬──────────────────────────────────┐
│ 我的历史问题    │  问答区（消息流）                  │
│ ┌───────────┐ │  ┌────────────────────────────┐ │
│ │ 新对话 +   │ │  │  用户问题（右侧气泡）          │ │
│ ├───────────┤ │  │  问：什么是四圣谛？            │ │
│ │ 什么是四圣谛│ │  └────────────────────────────┘ │
│ │ 缘起与十二…│ │  ┌────────────────────────────┐ │
│ │ What is…   │ │  │  AI 回答（左侧，markdown 流式）│ │
│ └───────────┘ │  │  ▸ 正在检索经文…              │ │
│               │  │  ┌────────────────────────┐ │ │
│               │  │  │ 引用经文（点击跳原文）     │ │ │
│               │  │  └────────────────────────┘ │ │
│               │  └────────────────────────────┘ │
│               │  ┌────────────────────────────┐ │
│               │  │ 输入框（追问）…      [↑]      │ │
│               │  └────────────────────────────┘ │
└───────────────┴──────────────────────────────────┘
```

### 3.1 我的历史问题

- **数据**：当前用户的历史提问（`ChatMessage` 中 `role=user`，按会话/问题分组）。
- **每条**：问题摘要 + 相对时间；当前会话高亮。
- **交互**：
  - 顶部「＋ 新对话」按钮；
  - 点击条目 → 切换当前会话（问答区刷新为该会话内容）；
  - 长按 / 悬停 → 删除该条历史。
- **未登录态**：提示 `登录后同步你的提问历史` + 登录按钮。
- **响应式容器**：
  - 手机：收起，顶部导航栏「历史」按钮打开（bottom-sheet 抽屉）；
  - 平板竖屏 / 横屏·桌面：常驻左侧栏。

### 3.2 问答区（主对话区）

- **用户问题**：右侧气泡，`paperRaised` 底 + 细线框。
- **AI 回答**：左侧，markdown 流式渲染（App 用 `react-native-streamdown`；Web 用 `Streamdown`）。
- **工具调用状态**：检索中显示 `正在检索经文…`（`retrieve_sutta_passage` 工具调用内联状态）。
- **引用卡片（citations）**：见 §3.3。
- **底部输入框（追问）**：与首页输入框同组件；回车 / 发送 → 追加追问。
- **操作**：
  - 流式中：`停止生成`；
  - 回答完成后：`复制` · `重新生成` · `有用 / 无用`（反馈）· `分享`（可选）。
- **空态（新对话）**：欢迎语 + 示例问题 chips（同首页 2.1）。
- **错误态**：`生成失败，请重试` + 重试按钮。

### 3.3 引用卡片（citations）与跳转

- **Schema**：`{ ref: string, passageId: string, pali: string, zh: string }`。
- **展示**：AI 回答内/下方内联渲染；每张卡片显示出处 `ref` + 经文片段（pali / zh）。
- **跳转**：点击 → 阅读器对应段落（`passageId` → `book` + `paragraph` → `Reader` 路由）。
- **实现**：CopilotKit 无等 `citations` 字段，经 **Generative UI / tool-call 渲染**（`useRenderTool({ name: "retrieve_sutta_passage", render })`）内联渲染，不改 `CopilotChat` 本体（详见 `README.md` §6.2）。

## 4. 响应式布局（手机 / 平板竖屏 / 平板横屏=电脑）

断点**以 `README.md` §4.2 为准**（本节只描述探索页在各档的形态，不另定义阈值）。按窗口宽度分档，不按设备类型；App 用 `useWindowDimensions().width`（dp），Web 为 CSS px：

| 档位 | 判定 | 首页 | 问答页 |
|---|---|---|---|
| **compact** | `< 600` | 单列：Hero 顶部 + 列表滚动 + 输入框**底部悬浮常驻** | 全屏对话；「我的历史问题」收起为抽屉（导航栏「历史」按钮） |
| **medium** | `600 – 839` | 单列**居中限宽**（≤720）；输入框底部常驻 | 左窄侧栏（历史问题 240–260）+ 右对话区 |
| **expanded** | `840 – 1199` | 居中限宽（≤800）；输入框升至 Hero 下方常驻；列表**三列卡片** | 左侧栏（280–320）+ 右对话区居中限宽 |
| **large** | `≥ 1200` | 居中限宽（≤840）；列表**四列卡片** | 左侧栏（280–320）+ 右对话区居中限宽 |

- 与 `README.md` §4.8 的 AI Chat 列保持一致：compact 全屏对话，medium 及以上「左历史右对话」。
- 导航容器沿 `README.md` §4.3：compact 底部 Tab bar；medium / expanded 左侧 rail（80）；large 常驻侧边栏（280）。
- 断点判定用 `useLayout()`（`README.md` §4.9），不在本页自行比较宽度。
- Web 额外增强（仅 Web，不影响 App）：鼠标悬停态、右键菜单、`Cmd/Ctrl + K` 聚焦输入框、内容区最大宽度避免超宽拉伸。

## 6. 数据契约与后端对接

沿用 `README.md` §7 的 mint `ChatController` / `ChatMessageController`，需**新增「公开问题 + 结构化 citations」模型与接口**：

| 目标接口 | 用途 | 现状 |
|---|---|---|
| `GET /chat?public=1&page=…` | 社区问答列表（分页） | ❌ 需新增公开问题字段/过滤 |
| `GET /chat/{id}` | 问题详情（messages + citations） | ⚠️ 需补 citations |
| `GET /chat?mine=1` | 我的历史问题 | ⚠️ 需补「我的」维度 |
| `POST /chat/{id}/messages` | 追问（或由 CopilotKit runtime 处理） | ⚠️ 需定义落库时机 |

**落库时序**（两层协同）：CopilotKit 负责**流式对话**（AG-UI SSE，经 runtime→backend→DeepSeek）；mint 的 `Chat`/`ChatMessage` 负责**持久化 + 公开问题存储**——一轮对话结束后写回 mint（含 citations），供「问答广场 / 我的历史问题」读取。衔接点仅两处：

1. 详情页「继续追问」→ 以该问题为上下文进入对话；
2. 回复内引用卡片点击 → 跳转阅读器段落。

**RAG 检索缺口**：当前 `agent-poc` 的 `retrieve_sutta_passage` 返回**平文本 mock**，需替换为接 mint `OpenSearchService`/`EmbeddingService` 的真实 RAG，并返回结构化 `citations`（`{ ref, passageId, pali, zh }`）。

## 7. 组件 / 路由规划（App 侧，Web 同构）

```
screens/chat/
  ChatHomeScreen.tsx     首页：Hero + Composer + Feed
  QuestionScreen.tsx     问答页：HistoryPanel + MessageList + Composer
components/chat/
  ChatHero.tsx           头部提示栏目
  ChatComposer.tsx       输入框（首页 / 追问复用）
  QuestionCard.tsx       社区列表卡片

  UserBubble.tsx         用户气泡

  CitationCard.tsx       引用卡片（tool-call 渲染）
```

- 导航类型新增：`Question: { chatId?: number; passageId?: string }`（`chatId` = 打开历史/公开问题详情；`passageId` = 阅读器「就此段落提问」带入上下文）。
- 现状对应：`AiChatScreen.tsx`（首页占位）→ `ChatHomeScreen`；`NewChatScreen.tsx`（复用 `CopilotChat`）→ `QuestionScreen` 定制对话层。

## 9. 验收要点（App / Web 一致）

1. 首页三区齐全：头部提示（含免责条 + 可点示例 chips）、输入框、社区列表（卡片含语言标签 + 引用标识）。
2. 问答页：历史问题可切换/删除，问答区流式输出，引用卡片点击跳转阅读器。
3. 响应式四档（compact / medium / expanded / large）：compact 单列（输入框底部常驻）；medium 单列限宽 + 左史右话；expanded 及以上双栏 + 多列卡片流。
4. App 与 Web 在任一断点下，文案、配色、组件行为一致。
